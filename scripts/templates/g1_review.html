Как проверять

  1. Распакуйте весь ZIP в одну папку и откройте index.html. Сначала прочитайте оба целых результата ниже. base.json и followup.json — полные неизменённые сохранённые ответы API.
  2. В строке проверки откройте PDF и указанную страницу, сопоставьте изображение, точную цитату и контекст. Красные рамки — указатели старого OCR; оригинальная страница без рамок доступна рядом. Координаты PDF даны в пунктах от верхнего левого угла, интервалы page_chars полуоткрытые [start,end) в сохранённом OCR.
  3. Для вывода модели проверьте, следует ли он из заявленных ссылок и условий: совпадения слов недостаточно. Неизвестные параметры договора не становятся фактами. «Фиксирована до конца 2027» — сообщение пользователя, не банковское доказательство.
  4. В каждой строке выберите «подтверждено / ошибка / недостаточно данных», напишите комментарий. Введите имя проверяющего и дату и нажмите «Скачать решения». Файл сохраните отдельно от исходного пакета. До скачивания правки хранятся только в открытой вкладке; перед закрытием экспортируйте их.

Файлы новостей — сохранённый HTML в безопасном текстовом виде и RSS, а не свежая версия сайта. Их изображения — явно подписанные производные визуализации. Октябрьские новости не используются как доказательства сентябрьского G1. У PDF неизвестен available_at; дата публикации не заменяет дату доступности.

У сохранённого контекста ACL version=1, у demo после теста отзыва прав — 2. Старый API может законно вернуть 404. Открывайте закреплённые ответы этого пакета; не меняйте права и не подменяйте исходный анализ другим g1-final-analysis.json. Read-only снимок хранилища содержит исходные версии, событие и сообщение follow-up.

Сохранить решения отдельно

Страница не изменяет API, Evidence, SourceVersion или human_verified. Импорт/экспорт работает локально, сетевых запросов нет. Незавершённую проверку тоже можно сохранить.



Пустой шаблон для внешнего редактора. Для автоматической проверки формата:

python -m scripts.review_g1 --output artifacts/integration/human-review --decisions artifacts/integration/decisions-reviewer.json
# Добавьте --require-complete для проверки полноты заполнения.

После проверки передайте JSON команде с packet_id. Принятое человеком решение записывается отдельной рецензией с автором, датой, claim/Evidence ID и SHA пакета. Исправления источника требуют новой версии; исходные доказательства и ответы не переписываются. Файл решений сам по себе не даёт human_verified и не заменяет независимую разметку.
