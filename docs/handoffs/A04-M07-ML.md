## Интерфейс для будущего engine

`contracts/ports.py::LLMClient`: `start_run(run_id, job_id=...)`, затем
`complete(LLMRequest, response_model) -> LLMResult[T]`. DTO остаются **1.1.0**;
новые LLMRequest/LLMResult и коды ошибок добавлены в JSON Schema/примеры. Старый
внутренний `complete(model_id, prompt) -> tuple` заменён; текущий fixture runner
его не использовал. HTTP маршруты анализа не менялись.

```python
from pydantic import BaseModel, ConfigDict
from app.llm.factory import create_gateway
from contracts.ports import LLMClient
from contracts.v1 import LLMRequest

class PlanReply(BaseModel):
    model_config = ConfigDict(extra="forbid")
    channels: list[str]
    missing_fields: list[str]

async def plan(engine, job_id, run_id, call_id, bounded_prompt):
    llm: LLMClient = create_gateway(engine)
    await llm.start_run(run_id, job_id=job_id)
    result = await llm.complete(LLMRequest(
        run_id=run_id, call_id=call_id,
        model_id="deepseek/deepseek-v4.1-flash",
        prompt=bounded_prompt, max_output_tokens=700, purpose="plan",
    ), PlanReply)
    return result.value, result.usage
```

Это пример интерфейса, не реализованный planner. Используйте компактные DTO шагов,
а не полный Analysis schema в каждом prompt. Схема добавляется шлюзом к system
message; provider structured-output/tool-calling не предполагается. Возвращается
JSON, проверенный `model_validate_json(..., strict=True)`; markdown fences, неверные
типы, extra fields при `extra=forbid`, truncation/tool response отклоняются.
Pydantic validation не доказывает смысловую поддержку claims: это будущий M04/M05.

Начинайте один стабильный `run_id` в начале анализа/follow-up, до поиска и tools;
привязывайте к настоящему `job_id` для защиты worker от неизвестного платного исхода.
Повтор start_run не сбрасывает deadline/счётчики. Каждый намеренный вызов имеет
уникальный стабильный `call_id`; повтор того же ID не отправляет запрос ещё раз,
даже если предыдущий результат известен. Результат completion не кешируется: engine
должен сохранять checkpoint/валидированный результат до перехода к следующему шагу.
Новый ID не является разрешением повторить неизвестный вызов.

Контроллер M04 продолжает использовать `RunBudget` для **12 transitions / 6 tools /
1 repeated search** и монотонного deadline. Gateway независимо и межпроцессно
обеспечивает **4 model calls / 24k input / 4k output / 60 s / 5 RUB hard reserve**,
не более 8k input на call, timeout до 12 s, 1 суммарный retry/fallback и 1 repair.
Фактические категории `purpose` задаёт серверный controller. Fallback/repair не
запускаются автоматически. Обычные output budgets: plan 700, draft 1700, verify 800;
engine распределяет остаток. Каждый неудачный начатый шаг расходует общий лимит;
неиспользованные token/cost верхние оценки run не возвращаются автоматически.

## Учёт, gate и отказоустойчивость

Миграция **0003** добавляет `llm_runs`, `llm_key_gates`, `llm_attempts`; существующие
CSV/pgvector/FTS таблицы не переписывает. Нужен `alembic upgrade head` перед live;
проверки выполнялись только в новых изолированных БД. Рабочая БД не мигрировалась.

Порядок: короткая DB-транзакция gate/run/attempt → ledger reserve (450/500 RUB,
03:00 Europe/Moscow) → durable mark_started → HTTP **без открытой DB-транзакции** →
provider usage → settlement → освобождение gate → Pydantic результата. В БД хранятся
request hash, лимиты, снимок тарифа и usage; prompt/ответ/ключ туда не записываются.
Scope выводится шлюзом из SHA-256 ключа, не принимается от клиента/LLM. Все участники
и процессы с одним ключом используют **одну PostgreSQL**, factory и общий ledger.
Несколько разных PostgreSQL не разделяют gate: это недопустимая конфигурация ключа.
Dev/eval/smoke используют тот же scope, без отдельных бюджетов или обходных clients.

HTTPX отправляет ровно одну попытку на фиксированный endpoint/allowlist инструкции;
SDK не используется, `max_retries=0`, transport retries=0, redirects/proxy-env выключены.
Резерв входных tokens — UTF-8 byte envelope messages + schema + 256 framing tokens;
это консервативная оценка, не проверенный tokenizer провайдера. Usage сверх envelope
учитывается полностью, ключ блокируется до проверки bound/тарифа оператором.
Проверка реального tokenizer/usage входит в M07. Tariff snapshot сохраняет точный Decimal.

Некорректный content при подтверждённом usage **оплачивается и settles**: расход не
исчезает из-за ошибки JSON. Некорректный envelope, другой model ID, отсутствующий/
противоречивый usage, timeout, cancel или потеря процесса удерживают резерв и gate.
HTTP 429 без подтверждённого usage тоже uncertain; нельзя предполагать нулевую оплату.
Подтверждённый usage на HTTP-ошибке учитывается; fallback только явным решением engine
в оставшейся квоте. Gate **не имеет auto-expiry**, в том числе после смены суток.
Worker использует прежние model_calls started/uncertain с job_id: unknown не requeue.

`LLMGateway.reconcile(call_id, input_tokens=..., output_tokens=...)` — только ручная
операторская процедура после независимого подтверждения **окончательного** usage и
завершения producer/provider call. Использует закреплённый тариф, idempotent ledger
settlement; снимает gate. Таймаут/429/отсутствие ответа не являются подтверждением
нулевого расхода. Зависший `preparing` до mark_started требует отдельной проверки
остановленного процесса и ledger оператором; автоматического сброса gate нет.

## Ошибки для engine

`GatewayError` — `AppError`, содержит `code`, `call_id`, optional `usage`,
`retryable=False`. Не логировать prompt/key/provider body, не показывать их пользователю.

| Код | Действие |
|---|---|
| backend_unavailable | Live off или ключ отсутствует; оставить synthetic/evidence-only |
| budget_unknown | Нет проверенного тарифа; ни одного HTTP-вызова |
| budget_exceeded | Daily/run/tokens/calls cap; stop, overrun требует проверки gate |
| deadline_exceeded | Run истёк до HTTP; stop |
| llm_busy | На ключе активный/неразобранный call; никакого обхода/нового scope |
| llm_outcome_unknown | Резерв удержан; partial + ручная сверка, без retry/fallback |
| llm_rate_limited | 429; если usage отсутствует, тоже uncertain; gateway не повторяет |
| llm_invalid_response | Расход подтверждён и учтён; возможен только явный bounded repair |
| idempotency_conflict / data_conflict | Нельзя переиспользовать call/run с другим смыслом |

## Конфигурация и отдельный model smoke

Synthetic запускается без ключа, тарифов и HTTP. `create_gateway` при live off не
читает tariff file. Сам флаг **не переключает fixture worker на ML**: M04 подключит
порт отдельно. `UnavailableLLMClient` остаётся явным stub, не transport для live.

Для live нужны `LIVE_LLM_ENABLED=true`, `LLM_API_KEY` в окружении процесса (не CLI,
не Git), `LLM_TARIFF_FILE=config/llm-tariffs.json` и рабочая общая DATABASE_URL.
Тарифный файл сейчас намеренно `{"tariffs":[]}`. Элемент tariffs содержит model_id,
version, input_rub_per_million/output_rub_per_million (decimal strings), verified=true,
evidence — ссылку/идентификатор подтверждения организаторов. Цены из названия модели
не выводятся. Подтверждение должно покрывать все billed tokens, включая reasoning/cache
и возможные fees; неподдержанную модель расчёта стоимости не включать. Неподтверждённый
тариф или конфликтующая конфигурация закрывает gate до HTTP.

Перед первым live нужны также подтверждение остатка общего ключа и одна общая БД.
Если сегодня уже были списания вне gateway, сначала сверить их с ledger; внешний
расход нельзя считать нулём.

После отдельного разрешения на **один** платный вызов, из настроенного окружения:

```bash
make model-smoke SMOKE_ARGS='--allow-paid --model deepseek/deepseek-v4.1-flash'
# либо внутри настроенного Compose:
docker compose run --rm worker python -m scripts.model_smoke --allow-paid --model deepseek/deepseek-v4.1-flash
```

Smoke использует тот же gateway/ledger/ключевой gate, output cap 64, DTO `{"ok":"ok"}`.
Без --allow-paid команда останавливается до обращения к БД/HTTP. Нет bypass для
unknown tariff. Наличие ключа само по себе не является разрешением провести smoke.
После успеха сверить recorded usage/RUB с провайдером; затем отдельно разрешать
проверку reserve model. M07 не засчитывается по offline mocks.
