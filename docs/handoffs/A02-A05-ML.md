## A05: инструменты для M04

`app.graph.service.CompanyTools(engine)` реализует ProfileProvider и RelationsProvider:

```python
tools = CompanyTools(engine)
profile = await tools.get_profile(context, company_id)
paths = await tools.get_relations(context, company_id)
```

На каждый вызов проверяются серверные grants и CLIENT/valid. Profile возвращает
authorized_subset; group sums/segment/refs не берутся из ранее сохранённой агрегации.
Отсутствие GROUP_ID не объединяет все такие компании в фиктивную группу.

В storage membership представлена `[U, F_or_group, U]`; tool разворачивает её в
`[authorized_U, F_or_group, authorized_U]` только внутри одного source version.
Обычные payment paths сохраняют направление. Скрытые и stub endpoints не возвращаются;
self-transfer не возвращается как exposure. Economic role всегда unknown.
Отзыв grants действует даже со старым context.grants. Порты не принимают as_of:
ML обязан применять TemporalAssessment к зависимостям перед аналитическим выводом.

A05 **частично**: profile/typed graph tools готовы; feed scoring, counterparty shares,
denominator coverage, case F_34348 trace и nDCG/абляции остаются отдельной работой.
Новые HTTP routes не добавлялись; synthetic worker не выдаёт себя за case engine.

## Подтверждённые ML-блокеры, исправленные интегратором

- `from ports` исправлен на `contracts.ports`; базовый import/audit не требует numpy/OCR.
- E5 разрешено читать только локальный cache (`local_files_only=True`), нет автозагрузки
  весов или внешних AI calls. Недоступность encoder честно выбирает lexical_fallback.
- Schema 0002 создаёт extension/embedding/FTS/indexes; ensure_pgvector_schema только
  проверяет наличие колонок. Для обновления существующей установки нужны новый DB image
  того же major 17 и `alembic upgrade head`, с обычным backup перед обновлением данных.
- Retrieval проверяет реальные grants до поиска, текущий context_version/компанию,
  domain документа и evidence. Future availability исключается также в snapshot;
  unknown availability допустима только в snapshot. Vector failure откатывается savepoint,
  поэтому lexical fallback не возвращается из сломанной PostgreSQL-транзакции.
- PDF SourceVersion ID теперь ASCII hash, допустимый DTO при кириллическом имени.
  Замена bytes под тем же document ID запрещена. Verified span требует совпадения SHA.
- Eval больше не засчитывает fallback как выполненный HNSW/Exact gate; no-answer violations
  тоже проваливают gate. Сами quality metrics на реальном корпусе не измерены.

`scripts/import.py CSV_DIR` теперь dry-run; `--apply` явно импортирует CSV;
`--pdf-dir PDF_DIR` вместе с `--apply` добавляет отдельный PDF этап.
CSV commit и PDF commit независимы: ошибка OCR не отменяет уже импортированный CSV;
статусы следует читать из отдельных manifest. PDF scope задаётся `--company-scope-id`.

## Remediation после независимого аудита

[Разбор находок, воспроизведение и полноразмерные замеры](../audits/d170154-remediation.md).
SQL payment cursor исправлен: INTEGER affinity first_row, проход по парам с indexed
row lookup вместо квадратичного JOIN. Writes идут binary COPY ограниченными пачками
(5000, profiles 250) в прежней атомарной транзакции. Payment payload/IDs совместимы
с прежними DTO; это проверено сравнением с reference Pydantic path. Ничего не суммируется
по неодинаковым парам, raw values/period/null/provenance сохранены.

Появился `python -m scripts.verify_full_import` для явно изолированной `/alfa_test`:
отдельные сценарии failure/apply/repeat, время/RSS/counts в JSON, полный audit и сверка
persisted PAY_AMT/PAY_CNT totals. Платных API нет. Production-size acceptance details
берутся из remediation, а не из прежнего небольшого CSV fixture.

Worker обрабатывает SIGTERM/SIGINT: bounded drain 5 s, cancellation и fenced release
без автоматического повтора started/uncertain model call. Uncertain reserve удерживается.
Реальный container PID 1 `docker stop` проверен: **1.05 s, exit 0**.

Новые миграции, DTO, import/source IDs, ML storage и layout не менялись.
Ограничение одного case snapshot на U и отказ от изменённого набора сохраняются.
