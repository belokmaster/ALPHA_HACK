## 2. Подключенные API-маршруты

Все запросы выполняются строго по контрактам `contracts/v1.py` (схема 1.1.0) и `contracts/openapi.json`:

| Действие пользователя | Маршрут | Метод | Заголовки / Тело | Ответ |
|---|---|---|---|---|
| Демо-авторизация | `/api/v1/demo/sessions` | `POST` | `{"actor": "alice" \| "bob"}` | HttpOnly cookie `alfa_session`, `csrf_token`, `UserContext` |
| Чтение контекста | `/api/v1/me/context` | `GET` | Cookie `alfa_session` | `UserContext` (id, principal, company_id, version, role, grants) |
| Смена компании/роли | `/api/v1/me/context` | `PATCH` | `X-CSRF-Token`, `{"expected_version": N, "company_id": "...", "role": "..."}` | Обновленный `UserContext` с `version: N+1` |
| Список компаний | `/api/v1/companies` | `GET` | Cookie `alfa_session` | `list[CompanyProfile]` в рамках прав grants |
| Персональная лента | `/api/v1/feed` | `GET` | Cookie `alfa_session` | `list[FeedItem]` (событие `rate_hold`, `reason_codes`, `delivery`) |
| Запуск анализа | `/api/v1/analyses` | `POST` | `X-CSRF-Token`, `Idempotency-Key: UUID`, `AnalysisRequest` | 202 Accepted, DTO `Job` (`id`, `status: queued`, `poll_url`) |
| Опрос воркера | `/api/v1/jobs/{id}` | `GET` | Cookie `alfa_session` | DTO `Job` (`status: queued\|running\|succeeded\|failed`, `result_id`) |
| Результат анализа | `/api/v1/analyses/{id}` | `GET` | Cookie `alfa_session` | DTO `Analysis` (sections, claims, evidence, notices, temporal) |
| Чтение доказательства | `/api/v1/evidence/{id}` | `GET` | Cookie `alfa_session` | DTO `Evidence` (quote, page, span, quality, document_version_id) |
| Текст документа-источника | `/api/v1/sources/{id}` | `GET` | Cookie `alfa_session` | DTO `Document` (title, publisher, published_at, text, url) |
| Уточняющий вопрос | `/api/v1/followups` | `POST` | `X-CSRF-Token`, `Idempotency-Key: UUID`, `FollowupRequest` (analysis_id, context_version, text, assumptions) | 202 Accepted, DTO `Job` с опросом через `poll_url` |
| Новости регулятора | `/api/v1/news` | `GET` | `?limit=20&source=cbr\|rosstat` | `list[Event]` из B02 news ingestion |
| Статусы источников | `/api/v1/news/sources` | `GET` | Cookie `alfa_session` | `list[NewsSourceState]` (cbr-press, rosstat) |

## 3. Пользовательский путь и компоненты интерфейса

### 3.1. Экран входа и оболочка банка
- Брендинг «Альфа-Бизнес» с фирменным стилем и явной отметкой «Демонстрационный прототип».
- Предупреждение о дисклеймере: «Не является индивидуальной инвестиционной рекомендацией. AI-выводы не являются официальной позицией банка».
- Выбор demo-пользователя (`alice` или `bob`) и кнопка «Войти через demo bank entry».
- Используется реальная demo-сессия сервера через `POST /api/v1/demo/sessions` с валидацией HttpOnly cookie и токена CSRF.

### 3.2. Верхняя панель контекста (Context Ribbon)
- Загрузка списка доступных компаний через `GET /api/v1/companies`.
- Отображение текущей активной компании (`ctx.company_id`) с возможностью выбора.
- Выбор роли (`unknown`, `ceo`, `cfo`).
- Выбор временного режима (`snapshot_demo` / `strict_as_of`) и даты актуальности `as_of`.
- Кнопка «Применить контекст» выполняет `PATCH /api/v1/me/context` с проверкой версионности `expected_version`.
- При смене компании:
  - немедленно отменяется активный polling;
  - очищается карточка анализа и боковая панель доказательств;
  - предотвращается отображение результатов старой компании в новом контексте.

### 3.3. Персональная лента («Лента событий компании»)
- Отображает записи из `GET /api/v1/feed`.
- Для каждого события выводятся:
  - заголовок публикации;
  - дата фиксации события и источник;
  - бейджи причин релевантности, возвращенные сервером (`synthetic_scenario` → «Учебный сценарий», `same_industry` → «Отраслевая привязка»). Никакие вымышленные проценты влияния не рассчитываются в JS.
  - кнопка «Анализировать событие» (активна для `rate_hold`).
  - честное предупреждение о том, что генерация подключена только для сценария `rate_hold`.

### 3.4. Карточка анализа (6 обязательных областей)
Структура `Analysis.sections` содержит списки ID утверждений. Интерфейс сопоставляет их с объектами `Analysis.claims` и никогда не выводит технические IDs вместо текста.
1. **Что произошло** (`happened`): базовые утверждения о событии.
2. **Почему важно для компании** (`relevance`): выводы модели об отраслевом влиянии.
3. **Возможные последствия** (`consequences`): гипотезы и сценарные прогнозы.
4. **На что обратить внимание** (`actions`): рекомендации и контрольные точки.
5. **Аналитика банка** (`bank_view`): позиция экспертов банка. При отсутствии подходящего тезиса (`bank_evidence_status = not_found`) выводится понятное объяснение: *«В доступных материалах подходящий банковский тезис не найден»*.
6. **Основания и ограничения** (`basis`): перечень ограничений и недостающих полей (`missing_fields`).

Каждое утверждение содержит:
- Тип (`fact` / `bank_view` / `ai_inference` / `hypothesis`);
- Источник происхождения (`external_source` / `bank_analysis` / `model` / `user_declared` / `synthetic`);
- Степень подтверждения (`supported` / `conditional` / `unsupported` / `conflicting`);
- Блоки условий (`conditions`) и альтернатив (`alternatives`), исключающие подмену условных выводов безусловными фактами.

### 3.5. Основания (Evidence Drawer)
- Кнопка «Основания» на каждом утверждении с привязанными источниками открывает выдвижную боковую панель.
- Цитата выводится строго через безопасный `textContent`.
- Отображаются метаданные документа: издатель, дата, место (страница PDF либо символьный диапазон `span`).
- Статус качества (`verified` / `unverified` / `unknown` / `conflict`) с предупреждением о непроверенном фрагменте/OCR.
- Кнопка «Показать полный текст документа» запрашивает исходный текст через `GET /api/v1/sources/{id}`.

### 3.6. Уточнение (Follow-up)
- Поле ввода вопроса (до 2000 символов с интерактивным счетчиком).
- Возможность заявить клиентское условие (`user_declared` assumption) с указанием ключа и значения (например, `rate: fixed through 2027`).
- Запрос отправляется с закрепленной версией контекста анализа (`analysis.context.version`).
- Защита от повторных кликов (блокировка и индикатор во время отправки).
- При сетевой или серверной ошибке введенный текст вопроса сохраняется в поле ввода.
- Отображение истории уточняющих вопросов в треде переписки.
- Явное предупреждение об ограничении `fixture_only`.

## 4. Обработка состояний и идемпотентность

- **Индикация опроса (Polling)**: отображение времени, статуса воркера (`queued` → `running` → `succeeded`), анимированного прогресса и кнопки прерывания опроса.
- **Идемпотентность**: для каждого запуска анализа и уточнения генерируется уникальный `Idempotency-Key` (UUID v4). При сетевой ошибке и повторе запроса используется тот же ключ; при новом действии — генерируется новый.
- **Остановка polling**: опрос автоматически завершается при достижении терминального статуса (`succeeded`, `failed`, `cancelled`), при смене компании/пользователя или нажатии кнопки отмены.
- **Состояния анализа**:
  - `ready` — готовый результат;
  - `partial` — частичный анализ с предупреждением о недостающих полях;
  - `insufficient_evidence` — недостаточность данных (например, при строгой дате `strict_as_of`);
  - `stale` — результат устарел (`delivery.stale = true`, причина `news_source_corrected`);
  - `saved_replay` — отображение даты и режима исходной генерации;
  - `failed` — отображение точного кода ошибки API (`ErrorCode`) и описания.

## 5. Режим UI-fixtures

Для проверки состояний, которые backend в текущей фазе не генерирует автоматически:
- В правом верхнем углу расположена кнопка **«Включить UI-fixtures»**.
- При включении наверху экрана постоянно виден желто-оранжевый баннер с предупреждением:
  *«⚠️ ТЕСТОВЫЕ ДАННЫЕ ИНТЕРФЕЙСА (UI Fixture Mode) — отображаются смоделированные сценарии для проверки интерфейса»*.
- В выпадающем списке доступны 7 сценариев:
  1. *Готовый анализ (Ready / Saved replay)*;
  2. *Частичный анализ (Partial / Missing bank evidence)*;
  3. *Недостаточно данных (Insufficient evidence / strict as_of)*;
  4. *Устаревший анализ (Stale / Source corrected)*;
  5. *Длинный текст и проверка XSS безопасности* (безопасное экранирование тегов `<script>`, `<b>`, длинных цитат);
  6. *Ошибка: Превышение бюджета (Budget exceeded 429)*;
  7. *Ошибка: Конфликт версии контекста (Context stale 409)*.
- Fixture-режим **не включается автоматически** при ошибках реального API (нет скрытых подмен).

## 6. Запросы интегратору и ограничения backend

1. **Генерация анализа для новостей регулятора (`/api/v1/news`)**:
   - Сейчас `POST /api/v1/analyses` принимает только `event_id = "rate_hold"` (для остальных возвращается 404).
   - *Запрос интегратору:* поддержать передачу `event_id` из сохраненных live новостей CBR/Росстата либо реализовать связывание новостных событий с кейсами.
2. **Банковская позиция (`bank_view`)**:
   - Сейчас в synthetic seed `bank_evidence_status` всегда возвращает `not_found`.
   - *Запрос интегратору:* после интеграции retrieval корпуса M01–M03 возвращать связанные `bank_view` claims со ссылками на страницы банковских PDF.
3. **Произвольные follow-up сценарии**:
   - Сейчас endpoint `followups` принимает только `scenario_id = "fixture_only"` (или `fixed_rate`).
   - *Запрос интегратору:* подключение LLM gateway (A04/M07) для свободных ответов на уточняющие вопросы клиентов.
