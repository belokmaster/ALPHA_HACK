# Локальные материалы

Все команды ниже выполняются из корня репозитория. Соседние каталоги не нужны.

В `docs/references/` оставлен только официальный Q&A организаторов без изменения
содержимого. Требования прежних планов, bootstrap-задания и вебинара сведены
в действующий [план](plan.md) и его дополнения: [решения](decisions.md),
[приёмку](requirements.md), [разбор Q&A](official-qa-impact.md).
Отдельные старые документы и дубли источников не сохраняются.
[Manifest](../config/inputs.manifest.json) задаёт пути относительно корня репозитория
(`root: "."`, `path_base: "repository_root"`), SHA-256, исходные статусы проверки
и `bundled`: входит ли материал в Git. Статус отражает историю проверки источника,
а не наличие файла в свежем checkout.

CSV/PDF распространяются отдельно. Поместите полученные материалы под указанными
в manifest именами в `raw/csv/` и `raw/pdf/`. Используйте обычные файлы, а не ссылки
на соседние каталоги. Эти каталоги исключены из Git и Docker build context.
Исходники при локальном переносе копируются побайтно, SHA-256 сохраняются.

Для полного импорта обязательны три файла:

- `raw/csv/df_Uid_data_hack.csv`
- `raw/csv/df_Fid_Uid_link_hack.csv`
- `raw/csv/df_Uid_payment_hack.csv`

```bash
make audit-inputs INPUT_DIR=raw/csv
make import-case INPUT_DIR=raw/csv
# Явная публикация в настроенную БД после проверки dry-run:
make import-case INPUT_DIR=raw/csv APPLY=--apply
```

Три manualcrop-варианта остаются в manifest для сохранения происхождения и SHA,
но сейчас отсутствуют локально и для полного импорта не требуются.
Наличие PDF, данных кейса и ключей не требуется для synthetic backend и его тестов.
Никаких платных API для подготовки материалов вызывать не нужно.

Исторические аудиторские отчёты сохраняют дословные диагностические команды
и пути среды аудитора. Эти цитаты не являются зависимостями проекта;
актуальные воспроизводимые команды приведены здесь и в передаче команде.
