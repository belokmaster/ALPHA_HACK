## Self-transfer: формулы и воспроизводимое расхождение №21

Для множества **R валидных исходных строк до dedup**, `S={r∈R | PAYER=BENEFICIARY}`:

- Доля суммы: `Σ(S.PAY_AMT) / Σ(R.PAY_AMT)`.
- Доля операций: `Σ(S.PAY_CNT) / Σ(R.PAY_CNT)`.
- Доля строк: `|S| / |R|`. Строка содержит агрегат и **не равна операции**.

| Метрика | Числитель | Знаменатель | Результат |
|---|---:|---:|---:|
| RUB | 45721727331000.0 | 55991235586000.0 | 81.6587218562% |
| Операции | 3258858 | 24515786 | 13.2928962588% |
| Строки | 27406 | 1380585 | 1.9851005190% |

Normalized множество исключает 1 точный дубль и 25 distinct variants из 9 неодинаковых
пар: 1380559 rows, сумма 55988541233000.0 RUB, 24515439 операций.
Self numerators неизменны; normalized доли **81.6626515428% / 13.2930844110% /
1.9851379043%** соответственно. Это **диагностика**, не полный exposure denominator
для affected payers и не доля выручки/закупок.

82% суммы близко к измерению. 3% операций не совпадает ни с ΣPAY_CNT, ни с долей строк;
смена знаменателя не устраняет расхождение. Остаётся вопрос о версии выборки/периметре
операций у организаторов. Используются все три canonical CSV, SHA указаны в
[audit summary](input-audit-summary.md); raw и нормализованные значения не меняются.

## №43–44: происхождение и смысл утверждения

Банковское evidence нужно при bank_view/использовании банковского тезиса, а не для
каждого инсайта. `bank_evidence_status=not_found` с пустым bank_view — допустимый
результат для внешнего факта/вывода. Полезный вклад банка остаётся целью продукта,
но не квотой на число банковских цитат в каждой карточке.

Контракт **1.1.0** явно разделяет `Claim.kind=fact|bank_view|ai_inference|hypothesis`
и `Claim.origin=external_source|bank_analysis|model|user_declared|synthetic|unknown`.
Новые claims требуют явный origin; hypothesis требует условия и conditional/unsupported,
не может выдаваться за supported fact. Внешний факт ссылается на evidence и document
publisher/source version, а не автоматически на банк. Сам URL не заменяет эту маркировку.
Fixture claims маркируются synthetic; генеративных вызовов нет.

Читатели принимают старые DTO 1.0.0: отсутствие origin остаётся unknown, не объявляется
банковским/внешним фактом. Для вывода новых данных consumers B/M должны обновить схемы:
старые readers с Literal 1.0.0 не поддерживают nullable end и новый claim kind.
Порты и HTTP paths прежние. Примеры/JSON Schema/OpenAPI пересобраны.

Semantic rule — `official-qa-2`, import version — `case-csv-2`: новые source/feature IDs.
Любой ранее импортированный `case-csv-*` набор другой версии отклоняется **до записи**;
автоматического изменения старых snapshots/analyses или рабочих БД нет. Нужны новая
изолированная БД/rebuild либо отдельная согласованная data migration. Исторические
замеры [remediation e538389](audits/d170154-remediation.md) относятся к case-csv-1;
они не доказывают корректность старого конца периода. Новый полный audit сверяет числа;
проверки COPY/atomicity новой семантики выполняются integration-тестами. Полный apply
case-csv-2 в этом узком проходе заново не измерялся.
